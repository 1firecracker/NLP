## 1. Introduction

### 1.1 Research Background

Prompt Engineering is a key technique for guiding Large Language Models (LLMs) to produce desired outputs. In In-Context Learning, the quality of demonstrations has a significant impact on model performance. This study aims to systematically analyze how different dimensions of prompt quality affect LLM performance in mathematical reasoning tasks.

### 1.2 Research Questions

Based on the theories of Wang et al. (2023) and Pan et al. (2023), this study explores the following questions:

1. **Demonstration Correctness**: How do incorrect demonstrations affect model performance?
2. **Demonstration Relevance**: What is the impact of irrelevant or partially relevant demonstrations?
3. **Demonstration Format Quality**: How does format inconsistency affect answer extraction and reasoning quality?

### 1.3 Theoretical Foundation

- **Wang et al. (2023)**: Found that in CoT prompts, demonstration correctness, reasoning step rationality, and format consistency are key factors
- **Pan et al. (2023)**: Proposed that models primarily perform "task recognition" rather than "task learning", where demonstration relevance and correctness are crucial

### 2.3 Experimental Design

We designed **3 dimensions with 10 experimental groups**:

#### Dimension 1: Demonstration Correctness
- **baseline**: Correct few-shot demonstrations
- **wrong_answer**: Incorrect answer demonstrations (correct reasoning, incorrect answer)
- **wrong_reasoning**: Incorrect reasoning steps (incorrect reasoning, answer may be correct)
- **completely_wrong**: Completely incorrect demonstrations

#### Dimension 2: Demonstration Relevance
- **baseline**: Relevant demonstrations
- **irrelevant**: Completely irrelevant demonstrations (code generation examples)
- **partially_relevant**: Partially relevant demonstrations (simple arithmetic problems)
- **mixed_50_50**: Mixed demonstrations (50% relevant + 50% irrelevant)

#### Dimension 3: Demonstration Format Quality
- **baseline**: Standard format (`#### number`)
- **format_inconsistent**: Inconsistent format (mixed formats)
- **format_missing**: Missing format markers (no `####`)
- **format_chaotic**: Chaotic format (reasoning and answer mixed together)

### 2.4 Evaluation Metrics

- **Accuracy**: Proportion of predicted answers that exactly match the correct answers
- **Error Types**: Extraction failure, completely wrong, close error (within ±5), format error
- **Token Usage**: Input/output token statistics
- **Processing Time**: Average processing time

#### 3.1.1 Basic Prompt Structure

**Method Description**:
All experimental groups share the same basic prompt structure, including system prompts, few-shot examples, and the current question. Specifically:
1. System prompt: Clearly states task requirements and output format (`#### number`)
2. Few-shot examples: Select different types of demonstrations based on `corruption_type`
3. Question format: Uniformly use "Question: [question text]"
4. Answer format: Uniformly use "Answer:\nLet's think step by step.\n[reasoning process]"

This unified structure ensures that all experimental groups have consistent prompt formats, with only demonstration content differing, facilitating fair comparison.

```python
def nshot_chats_corrupted(n: int, question: str, corruption_type: str = None) -> list:
    """Build prompt using corrupted demonstrations"""
    
    def question_prompt(s):
        return f'Question: {s}'

    def answer_prompt(s):
        return f"Answer:\nLet's think step by step.\n{s}"

    # System prompt
    chats = [
        {"role": "system", "content": 
         "Your task is to solve a series of math word problems by providing the final answer. Output format: #### integer . e.g.: #### 16 if the answer is 16"}
    ]

    # Select different demonstrations based on corruption_type
    demos = get_corrupted_demonstrations(corruption_type, n)
    
    # Add few-shot examples
    for q, a in demos:
        chats.append({"role": "user", "content": question_prompt(q)})
        chats.append({"role": "assistant", "content": answer_prompt(a)})

    # Add current question
    chats.append({"role": "user", "content": question_prompt(question)})
    return chats
```

#### 3.1.3 Incorrect Answer Demonstrations (wrong_answer)

**Method Description**:
This method creates incorrect demonstrations by modifying the final answer in demonstrations while keeping reasoning steps completely correct. Specifically:
1. Extract numbers from the original answer (via regex matching `#### number`)
2. Apply random offset to the answer number (±1 to ±5)
3. Replace the answer part while keeping reasoning steps unchanged

This creates demonstrations with correct reasoning processes but incorrect final answers, used to test whether the model will be misled by incorrect answers.

```python
def corrupt_answer_only(question: str, answer: str) -> str:
    """Corrupt only the answer, keeping reasoning steps correct"""
    match = re.search(r'####\s*(\d+)', answer)
    if match:
        original_ans = int(match.group(1))
        # Generate incorrect answer (random offset of ±1-5)
        wrong_ans = original_ans + random.randint(-5, 5)
        if wrong_ans < 0:
            wrong_ans = abs(wrong_ans)
        if wrong_ans == original_ans:
            wrong_ans = original_ans + 1
        # Replace answer
        corrupted = re.sub(r'####\s*\d+', f'#### {wrong_ans}', answer)
        return corrupted
    return answer
```

**Prompt Example**:
```
Assistant: Answer:
Let's think step by step.
There are 15 trees originally. Then there were 21 trees after the Grove workers planted some more. So there must have been 21 - 15 = <<21-15=6>>6 trees that were planted.
#### 7  # Note: Answer changed from 6 to 7, but reasoning steps are correct
```

#### 3.1.4 Incorrect Reasoning Steps (wrong_reasoning)

**Method Description**:
This method creates incorrect reasoning by modifying intermediate calculation steps in demonstrations, but the final answer may coincidentally be correct. Specifically:
1. Identify all calculation expressions in reasoning steps (format `<<expression=result>>`)
2. Randomly modify each calculation result (±1 to ±3)
3. Keep the final answer unchanged (may coincidentally be correct)

This creates demonstrations with incorrect reasoning processes but potentially correct final answers, used to test whether the model primarily focuses on answers rather than reasoning processes.

```python
def corrupt_reasoning_only(question: str, answer: str) -> str:
    """Corrupt only reasoning steps, answer may coincidentally be correct"""
    def corrupt_calculation(match):
        expr = match.group(1)
        result = match.group(2)
        try:
            # Randomly modify calculation result
            new_result = int(result) + random.randint(-3, 3)
            if new_result < 0:
                new_result = abs(new_result)
            return f"<<{expr}={new_result}>>"
        except:
            return match.group(0)
    
    corrupted = re.sub(r'<<([^=]+)=(\d+)>>', corrupt_calculation, answer)
    return corrupted
```

**Prompt Example**:
```
Assistant: Answer:
Let's think step by step.
There are 15 trees originally. Then there were 21 trees after the Grove workers planted some more. So there must have been 21 - 15 = <<21-15=7>>7 trees that were planted.  # Note: Calculation error (should be 6)
#### 6  # Answer coincidentally correct
```

#### 3.1.5 Completely Incorrect Demonstrations (completely_wrong)

**Method Description**:
This method creates completely incorrect demonstrations, including incorrect reasoning steps and incorrect final answers. Specifically:
1. First apply `corrupt_reasoning_only` to modify reasoning steps
2. Then apply `corrupt_answer_only` to modify the final answer

This creates demonstrations that are incorrect in both reasoning and answer dimensions, used to test the model's tolerance for completely incorrect demonstrations.

```python
def corrupt_completely(question: str, answer: str) -> str:
    """Complete corruption: both reasoning and answer are incorrect"""
    # First corrupt reasoning
    corrupted = corrupt_reasoning_only(question, answer)
    # Then corrupt answer
    corrupted = corrupt_answer_only(question, corrupted)
    return corrupted
```

**Prompt Example**:
```
Assistant: Answer:
Let's think step by step.
There are 15 trees originally. Then there were 21 trees after the Grove workers planted some more. So there must have been 21 - 15 = <<21-15=7>>7 trees that were planted.  # Reasoning error
#### 8  # Answer also incorrect
```

#### 3.1.8 Mixed Demonstrations (mixed_50_50)

**Method Description**:
This method creates mixed demonstrations containing 50% relevant and 50% irrelevant demonstrations. Specifically:
1. Select 4 from relevant demonstrations (GSM8K examples)
2. Select 4 from irrelevant demonstrations (code generation examples)
3. Randomly shuffle and combine

This creates demonstrations with moderate diversity, used to test whether diversity helps improve model performance (based on Naik et al., 2023's diversity of thought theory).

```python
def get_mixed_demonstrations(relevant_ratio: float = 0.5):
    """Get mixed demonstrations (50% relevant + 50% irrelevant)"""
    n_relevant = int(8 * relevant_ratio)  # 4 relevant
    n_irrelevant = 8 - n_relevant  # 4 irrelevant
    
    relevant = list(gsm8k_nshots[:n_relevant])
    irrelevant = get_irrelevant_demonstrations()[:n_irrelevant]
    
    # Randomly mix
    mixed = relevant + irrelevant
    random.shuffle(mixed)
    return mixed[:8]
```

**Prompt Example**:
```
User: Question: [Relevant math problem 1]
Assistant: [Relevant answer 1]

User: Question: Write a Python function...
Assistant: [Code generation answer]

User: Question: [Relevant math problem 2]
Assistant: [Relevant answer 2]

User: Question: [Code problem]
Assistant: [Code answer]

# ... Mix 4 relevant and 4 irrelevant demonstrations
```

#### 3.1.9 Inconsistent Format (format_inconsistent)

**Method Description**:
This method creates format-inconsistent demonstrations using different answer formats across different examples. Specifically:
1. Cycle through 4 different formats for 8 demonstrations:
   - Format 1: `Answer: number`
   - Format 2: `答案是: number` (Chinese)
   - Format 3: `The answer is number` (English)
   - Format 4: `#### number` (standard format)
2. Keep reasoning step format consistent

This creates demonstrations with inconsistent answer formats, used to test the importance of format consistency for answer extraction.

```python
def get_format_inconsistent_demonstrations():
    """Get format-inconsistent demonstrations"""
    inconsistent = []
    for i, (q, a) in enumerate(gsm8k_nshots):
        answer_match = re.search(r'####\s*(\d+)', a)
        if answer_match:
            answer_num = answer_match.group(1)
            # Use different formats
            if i % 4 == 0:
                new_a = a.replace(f'#### {answer_num}', f'Answer: {answer_num}')
            elif i % 4 == 1:
                new_a = a.replace(f'#### {answer_num}', f'答案是: {answer_num}')
            elif i % 4 == 2:
                new_a = a.replace(f'#### {answer_num}', f'The answer is {answer_num}')
            else:
                new_a = a  # Keep original format
            inconsistent.append((q, new_a))
    return inconsistent
```

**Prompt Example**:

Assistant: Answer:

#### 3.1.10 Missing Format Markers (format_missing)

**Method Description**:
This method creates demonstrations missing key format markers by removing `####` markers while keeping answer numbers. Specifically:
1. Extract answer numbers from original demonstrations
2. Remove `####` markers
3. Keep only answer numbers at the end of text

This creates demonstrations missing standard format markers, used to test the answer extractor's dependence on `####` markers.

```python
def get_format_missing_demonstrations():
    """Get demonstrations missing key format (no #### markers)"""
    missing_format = []
    for q, a in gsm8k_nshots:
        # Remove #### markers but keep answer numbers
        a_no_format = re.sub(r'####\s*(\d+)', r'\1', a).strip()
        missing_format.append((q, a_no_format))
    return missing_format
```

**Prompt Example**:
```
Assistant: Answer:
Let's think step by step.
There are 15 trees originally. Then there were 21 trees after the Grove workers planted some more. So there must have been 21 - 15 = <<21-15=6>>6 trees that were planted.
6  # Note: No #### marker, only number
```

#### 3.1.11 Chaotic Format (format_chaotic)

**Method Description**:
This method creates chaotically formatted demonstrations by mixing answers into reasoning steps. Specifically:
1. Extract answer numbers from original demonstrations
2. Remove `####` markers and line breaks
3. Mix answers into the end of reasoning steps in the form "The final answer is X."

This creates demonstrations without clear answer separation, with answers mixed with reasoning steps, used to test the impact of chaotic format on answer extraction.

```python
def get_format_chaotic_demonstrations():
    """Get chaotically formatted demonstrations (reasoning and answer mixed together)"""
    chaotic = []
    for q, a in gsm8k_nshots:
        answer_match = re.search(r'####\s*(\d+)', a)
        if answer_match:
            answer_num = answer_match.group(1)
            # Mix answer into reasoning steps
            chaotic_answer = a.replace(f'\n#### {answer_num}', f' The final answer is {answer_num}.')
        else:
            chaotic_answer = a
        chaotic.append((q, chaotic_answer))
    return chaotic
```

**Prompt Example**:
```
Assistant: Answer:
Let's think step by step.
There are 15 trees originally. Then there were 21 trees after the Grove workers planted some more. So there must have been 21 - 15 = <<21-15=6>>6 trees that were planted. The final answer is 6.  # Note: Answer mixed in reasoning, no #### marker
```

## 4. Experimental Results

### 4.1 Overall Results Overview

| Dimension | Experimental Group | Accuracy | Change from Baseline | Key Findings |
|-----------|-------------------|----------|---------------------|--------------|
| **Correctness** | baseline | 35.71% | - | Baseline |
| | wrong_reasoning | 36.69% | +2.76% | Incorrect reasoning has minimal impact |
| | completely_wrong | 34.72% | -2.76% | Complete errors have small impact |
| | wrong_answer | 33.66% | -5.73% | Incorrect answers have moderate impact |
| **Relevance** | baseline | 35.71% | - | Baseline |
| | mixed_50_50 | **37.38%** | **+4.67%** | ⭐ Mixed demonstrations perform best |
| | partially_relevant | 16.22% | -54.56% | Partial relevance has large negative impact |
| | irrelevant | 9.86% | -72.40% | Complete irrelevance nearly fails |
| **Format** | baseline | 35.71% | - | Baseline |
| | format_inconsistent | 0.38% | -98.94% | Format inconsistency nearly fails |
| | format_missing | 0.00% | -100% | Missing format completely fails |
| | format_chaotic | 0.00% | -100% | Chaotic format completely fails |

### 4.2 Key Findings

1. **Format quality is the most critical factor**: All format-related experiments achieved accuracy close to 0%, indicating that format is crucial for answer extraction.

2. **Demonstration relevance has significant impact**: Irrelevant demonstrations caused a 72.40% drop in accuracy, approaching zero-shot levels.

3. **Demonstration correctness has small impact**: Incorrect demonstrations only caused a 2-6% drop in accuracy, indicating the model has high tolerance for demonstration errors.

4. **Advantage of mixed demonstrations**: Mixed demonstrations (50% relevant + 50% irrelevant) achieved 4.67% higher accuracy than baseline, supporting the diversity of thought theory.

## 5. Conclusions

This study systematically analyzed the impact of prompt quality on LLM mathematical reasoning capabilities. The main findings are:

1. **Format quality is the most critical factor**: Format issues caused a 98-100% drop in accuracy, making it the factor with the greatest impact.

2. **Demonstration relevance has significant impact**: Irrelevant demonstrations caused a 72.40% drop in accuracy, indicating that models primarily perform task recognition rather than task learning.

3. **Demonstration correctness has small impact**: Incorrect demonstrations only caused a 2-6% drop in accuracy, indicating the model has high tolerance for demonstration errors.

4. **Advantage of mixed demonstrations**: Mixed demonstrations (50% relevant + 50% irrelevant) performed best (+4.67%), supporting the diversity of thought theory.

These findings provide important guidance for prompt engineering: **format consistency is more important than demonstration correctness, and moderate diversity may improve performance**.
